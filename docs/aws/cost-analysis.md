# AWS Cost Analysis — RAGScale Project

## 1. Introduction

This document evaluates the cloud infrastructure costs associated with the RAGScale project. Amazon S3 is used for cloud storage of benchmark results, while Pinecone provides managed vector storage and similarity search.

The objective is to identify the main cost components, monitor resource consumption, and minimize unnecessary cloud expenses.

## 2. AWS Infrastructure Configuration

| Component | Configuration |

- pinecone_latency_results.json

- pinecone_scaling_10k_results.json

These files preserve latency, recall, and scaling experiment results for future evaluation.

## 4. Cost Components

### 4.1 S3 Storage Cost

Amazon S3 Standard storage is charged according to the amount of data stored and the applicable regional pricing.

The project currently stores small JSON benchmark artifacts rather than the complete original dataset.

Storage cost depends on:
- Total stored data in GB.
- Storage duration.
- Applicable Sydney regional pricing.

### 4.2 S3 Request Cost

Potential request-related charges include:

- PUT requests for uploading files.
- GET requests for downloading files.
- LIST requests for browsing objects.

The project minimizes unnecessary requests by reusing existing benchmark artifacts.

### 4.3 Data Transfer Cost

Data transfer may incur charges when objects are transferred between AWS regions or from AWS to external services.

The RAGScale architecture currently has:
- S3 in Sydney (ap-southeast-2).
- Pinecone in US East (us-east-1).

Cross-region transfer implications are documented separately in cross-region-analysis.md.

### 4.4 Pinecone Usage

Pinecone is a separate managed vector database service and is not an AWS S3 billing component.

Recorded Starter-plan usage at the time of monitoring:

| Resource | Recorded Usage | Displayed Limit |
|---|---:|---:|
| Storage | 0.067 GB | 2 GB |
| Write Units | 84K | 2M |
| Read Units | 2 | 1M |

These are historical dashboard readings, not a current billing statement or a guarantee of zero charges.

## 7. Cost Optimization Strategy

The following practices are recommended:

1. Store only required benchmark artifacts in S3.
2. Avoid unnecessary repeated uploads.
3. Avoid enabling paid CloudWatch custom metrics.
4. Do not create unused EC2 or RDS instances.
5. Monitor AWS billing regularly.
6. Avoid unnecessary cross-region data transfers.
7. Reuse existing Pinecone indexes and namespaces.
8. Avoid unnecessary vector re-upload operations.

## 8. Cost Calculation Methodology

The project's actual cost should be calculated using verified billing data.

A simplified cost model is:

**Total Cloud Cost = S3 Storage Cost + S3 Request Cost + Data Transfer Cost + Other AWS Service Charges**

Pinecone charges, if applicable, should be reported separately.

No exact monetary cost is claimed in this report because verified billing amounts were unavailable.

## 9. Conclusion

The RAGScale project established an S3-based cloud storage layer for benchmark artifacts and configured basic budget monitoring.

The implementation emphasizes limited storage usage, encryption, restricted public access, and avoiding unnecessary cloud resources.

Actual AWS expenditure and applicable Pinecone charges must be confirmed through their respective billing dashboards before reporting a final monetary cost.
