# AWS Cloud Architecture — RAGScale Project

## 1. Introduction

The RAGScale project uses Amazon Web Services (AWS) as its cloud storage layer to support document intelligence and benchmark result management.

The architecture combines AWS S3 with two vector database approaches: PostgreSQL with pgvector and Pinecone.

The objective is to evaluate vector database performance while maintaining a cloud-based storage and document management layer.

## 2. Architecture Overview

The proposed RAGScale architecture consists of the following components:

1. Document storage using Amazon S3.
2. Document processing and embedding generation.
3. PostgreSQL with pgvector for relational vector storage.
4. Pinecone for dedicated cloud vector storage.
5. A common retrieval and evaluation layer.
6. An LLM-based response generation component.

## 3. AWS Infrastructure

### 3.1 Amazon S3

Amazon S3 provides object storage for project artifacts.

Configuration:

| Parameter | Value |
|---|---|
| Service | Amazon S3 |
| Region | ap-southeast-2 |
| Location | Asia Pacific (Sydney) |
| Bucket Type | General Purpose |
| Storage Class | S3 Standard |
| Encryption | SSE-S3 |
| Folder | benchmarks/ |

### 3.2 Stored Objects

The benchmarks folder stores JSON files generated by Pinecone experiments.

These include:
- Latency benchmark results.
- Recall benchmark results.
- 1K scaling results.
- 10K scaling results.
- Upload summary information.

### 3.3 Security

The S3 bucket uses server-side encryption with Amazon S3 managed keys (SSE-S3).

Public access is restricted through the bucket's access configuration.

AWS credentials and Pinecone API keys are kept outside the source repository.

## 4. Vector Database Architecture

The project evaluates two vector database approaches.

### 4.1 PostgreSQL with pgvector

PostgreSQL provides relational database functionality with vector similarity search through pgvector.

The implementation evaluates:

- Exact vector search.
- HNSW indexing.
- IVFFlat indexing.
- Query latency.
- Recall.
- Index build time.
- Dataset scalability.

The existing PostgreSQL benchmark environment runs locally on Windows.

### 4.2 Pinecone

Pinecone provides a managed vector database for cloud-based similarity retrieval.

The project uses:
- Index: ragscale-arxiv
- Dimensions: 384
- Original dataset: 20,000 vectors
- Additional scaling namespaces: scale-1k and scale-10k
- Similarity search and latency evaluation.

## 5. Proposed End-to-End Data Flow

The intended unified RAG workflow is:

1. Documents are stored in Amazon S3.
2. The ingestion pipeline retrieves documents from S3.
3. Document text is extracted and divided into chunks.
4. An embedding model converts text into numerical vectors.
5. Vectors are stored in PostgreSQL or Pinecone.
6. User queries are converted into embeddings.
7. The selected vector backend retrieves relevant documents.
8. Retrieved context is passed to an LLM.
9. The LLM generates a context-based response.
10. Benchmark and evaluation results are stored in S3.

Note: S3-to-ingestion and unified backend integration are planned components and are not yet verified as a working end-to-end workflow.

## 6. Regional Architecture

The current deployment uses two different geographical regions:

| Component | Region |
|---|---|
| Amazon S3 | ap-southeast-2 (Sydney) |
| Pinecone | us-east-1 (US East) |
| PostgreSQL | Local Windows environment |

The regional difference may influence network latency and data transfer costs.

Further details are provided in cross-region-analysis.md.

## 7. Cost and Resource Management

The architecture follows a cost-conscious deployment strategy.

Measures include:

- Reusing existing AWS S3 infrastructure.
- Avoiding unnecessary cloud resource creation.
- Using existing Pinecone namespaces.
- Storing only required benchmark artifacts.
- Monitoring storage and request usage.
- Configuring an AWS Zero-Spend Budget notification.

A budget notification is not a hard spending limit.

## 8. Architecture Benefits

The proposed architecture offers:

1. Separation between cloud object storage and vector databases.
2. Flexibility to compare relational and dedicated vector databases.
3. Reusable document processing and embedding components.
4. Centralized benchmark artifact storage.
5. Support for scalable RAG experimentation.
6. Independent evaluation of retrieval performance.

## 9. Conclusion

The RAGScale architecture combines AWS S3, PostgreSQL with pgvector, and Pinecone to evaluate cloud-based document intelligence architectures.

AWS S3 provides cloud object storage, while PostgreSQL and Pinecone provide alternative vector retrieval approaches.

The final unified architecture will connect document ingestion, embedding generation, vector retrieval, and response generation through a common RAG pipeline.

The implementation and integration status of each component will be verified separately before final deployment claims are made.
